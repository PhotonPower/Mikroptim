# ADR-0015: CUDA 13 erlaubt, Tesla P100 entfällt

- **Status:** angenommen
- **Datum:** 2026-10-29
- **Ersetzt:** ADR-0002

## Kontext

ADR-0002 legte CUDA 12.x fest, weil CUDA 13 Maxwell, Pascal und Volta nicht mehr unterstützt und die Tesla P100 (sm_60) als FP64-Rechner vorgesehen war. Die P100 steckt im Server herkules (etwa 15 Jahre alt, 128 GB RAM). Dort ist inzwischen nur noch der offene Kerneltreiber der Serie 590 installiert, der Pascal nicht unterstützt; der Maintainer stellt herkules nicht mehr um (Oktober 2026). Rechner für Mikroptim sind damit:

| | RTX 3090 (Arbeitsplatz-PC, Windows) | RTX 6000 Ada (herkules3, RHEL 10, 1 TB RAM) |
|---|---|---|
| Architektur | Ampere, sm_86 | Ada, sm_89 |
| Speicher | 24 GB | 48 GB |
| FP64 | ca. 1/64 der FP32-Rate | ca. 1/64 der FP32-Rate |

## Entscheidung

- Die Tesla P100 ist keine Zielhardware mehr. Es gibt keine GPU mit schneller FP64-Einheit im Projekt.
- CUDA **12.x oder 13.x** (mindestens 12.0; empfohlen das neueste installierte, perspektivisch 13). CMake bricht bei CUDA 13 nicht mehr ab.
- `CMAKE_CUDA_ARCHITECTURES = 86-real;89-real;89-virtual` (RTX 3090, RTX 6000 Ada, PTX für neuere Karten). Untergrenze sm_86.
- Treiber ohne Einschränkung auf Pascal-fähige Serien.

## Konsequenzen

- Features bis sm_86 dürfen ohne Fallback verwendet werden (z. B. größerer Shared Memory per Opt-in, Warp-Reduktionen `__reduce_*_sync` für Ganzzahlen); FP64-Rechenwege bleiben, Tensor Cores weiter nicht.
- Produktionsläufe auf beiden Karten mit df64 (M7-T1) prüfen; FP64 bleibt Referenz, ist aber auf beiden Karten langsam.
- Offene Abnahmen „auf der P100“ (M2, M7-T3) entfallen; Mehr-GPU-Läufe (M7-T3) sind nur noch mit mehreren Karten in einem Rechner sinnvoll, was derzeit keiner hat. Der Code bleibt, die Tests überspringen ohne zweites Gerät.
- Die Diskussion zur Bitgleichheit zwischen sm_60 und sm_86 ist gegenstandslos (seit ADR-0013 ohnehin keine Anforderung).
- Die CI kompiliert mit CUDA 12.9 und 13.0, damit beide Toolkits gültig bleiben. CUDA 13 hat `cudaDeviceProp::singleToDoublePrecisionPerfRatio` entfernt; das FP32:FP64-Verhältnis kommt jetzt aus `cudaDeviceGetAttribute(…, cudaDevAttrSingleToDoublePrecisionPerfRatio, …)` (auch unter 12.x vorhanden).
- Laufzeitprüfung: `TraceEngine` und `usable_devices()` lehnen Geräte unter sm_86 ab (`kMinComputeCapability = 86`), weil das Programm für ältere Karten keinen Code enthält.

## Verworfene Alternativen

- **P100 mit proprietärem Treiber R580 weiter betreiben:** vom Maintainer verworfen (Rechner zu alt, kein Aufwand mehr).
- **Sofort nur CUDA 13:** herkules3 hat derzeit CUDA 12.9; beide Toolkits zu erlauben, kostet nur einen CI-Job.
